# Pilot deployment guide

This guide puts AgroAI live for a real pilot: real accounts, a shared online database, live
weather, manual soil tests and (optionally) a field sensor station. It uses only free tiers.

| Part | Service | Cost |
|---|---|---|
| Database | [Supabase](https://supabase.com) (PostgreSQL) | Free tier |
| API server | [Render](https://render.com) web service, built from this repository | Free tier |
| Website | GitHub Pages (this repository) | Free |
| Weather | [Open-Meteo](https://open-meteo.com) | Free for non-commercial use |

Expect about 30 minutes. You need the GitHub account that owns this repository.

```
Browser ──► GitHub Pages (website) ──► Render (AgroAI API) ──► Supabase (PostgreSQL)
Sensor station ─────────────────────────┘        └──► Open-Meteo (weather)
```

The database starts **empty**: no demo farm and no accounts. The API creates the tables the
first time it starts.

---

## 1. Create the database (Supabase)

1. Sign up at <https://supabase.com> and choose **New project**.
2. Name it `agroai`. Click **Generate a password** and save it in a password manager; you will
   need it in a moment and Supabase will not show it again.
3. Pick the region closest to Lesotho that is offered, then **Create new project**. Wait a
   minute or two for it to finish.
4. Click **Connect** in the project's top bar. Under **Connection string**, choose
   **Session pooler** and copy the URI. It looks like:

   ```
   postgresql://postgres.abcdefghijkl:[YOUR-PASSWORD]@aws-0-eu-west-1.pooler.supabase.com:5432/postgres
   ```

5. Replace `[YOUR-PASSWORD]` with your database password and add `?sslmode=require` to the end.
   This full string is your **database URL**. Treat it like a password.

> Use the **Session pooler** string. The *Direct connection* needs IPv6, which Render's free
> tier lacks, and the *Transaction pooler* (port 6543) is not suited to this API.

## 2. Deploy the API (Render)

1. Sign up at <https://render.com> with your GitHub account and allow it to see
   `KentTolo/AgroAI-Version2`.
2. Choose **New → Blueprint**, select the repository and confirm. Render reads
   [`render.yaml`](../../render.yaml) and proposes one service, `agroai-api`.
3. Fill in the two values it asks for:

   | Variable | Value |
   |---|---|
   | `AGROAI_DATABASE_URL` | The database URL from step 1 |
   | `AGROAI_ADMIN_EMAILS` | The email address you will register with (your admin account) |

   Everything else is preset. `AGROAI_SECRET_KEY` is generated by Render automatically.
4. Click **Apply**. The first build takes about 5 to 10 minutes (it installs dependencies and
   trains the model).
5. When it shows **Live**, copy the service URL, for example
   `https://agroai-api.onrender.com` (yours may have extra characters).
6. Open `<your API URL>/health/ready` in a browser. You should see
   `"database":"ok"` and a model version. If not, see [Troubleshooting](#troubleshooting).

## 3. Switch the website to the live system (GitHub Pages)

The [Pages workflow](../../.github/workflows/pages.yml) builds the live system by default, pointed
at the pilot API (`https://agroai-api-c9cq.onrender.com`). Every push to `main` redeploys it.

- **Different API address** (for example a new Render service): add the repository variable
  `AGROAI_API_URL` under **Settings → Secrets and variables → Actions → Variables**, set to the
  bare API URL with no trailing slash and no `/api/v1`.
- **Back to the browser-only demo:** add the variable `AGROAI_DEMO` with the value `true`.

After changing a variable, open **Actions → Deploy web app to GitHub Pages → Run workflow**.

## 4. Start the pilot

1. Open the website and **Create account** using the email you set as `AGROAI_ADMIN_EMAILS`.
   Choose your own password; nobody else ever sees it.
2. Open the account menu (top right): **Admin dashboard** is there. It shows every user, field,
   station and recommendation across the system.
3. **Fields → Add field**: name it (e.g. "Home field"), enter its size, and click your field on
   the map (or type the coordinates from your phone's map app). Weather history for that spot
   downloads automatically when you open the field.
4. **Add reading**: enter your soil test results (nitrogen, phosphorus, potassium, pH). For
   temperature, humidity and rainfall, enter anything sensible; you will take them from the
   weather feed instead.
5. **Recommend**: choose your field, set **Climate source** to *typical climate for a season*,
   pick your planting month, and run the recommendation. It combines your soil test with years of
   local weather.
6. Optional: on the field page, **Field sensors → Add station** to get the key for the sensor
   station, then follow the [sensor station guide](../hardware/README.md).

### Getting soil values

The model needs N, P and K (kg/ha) and pH from a soil test. Use a soil testing laboratory if
you can; a home NPK and pH test kit is a cheaper, rougher alternative. Test again each season.

## Operating notes

- **Cold starts.** Render's free service sleeps after 15 minutes without traffic, so the first
  page load after a quiet spell can take about a minute. A sensor station reporting every 15
  minutes keeps it awake. Free services get 750 hours a month, enough for one service running
  continuously.
- **Inactive databases.** Supabase pauses free projects after a week without activity. The
  station's readings count as activity; if the project does pause, restore it from the Supabase
  dashboard.
- **Backups.** The free tier has no automatic backups you can restore yourself. Take a copy now
  and then with `pg_dump "<database URL>" > agroai-backup.sql` (requires PostgreSQL client tools).
- **Weather limits.** Open-Meteo's free tier allows 10,000 requests a day per server. A field's
  first sync uses roughly 100; later syncs only fetch the last week.
- **Updates.** Every push to `main` redeploys both the website and (via Render's auto-deploy)
  the API. Database migrations run automatically when the API starts.
- **Secrets.** Never commit the database URL. If it leaks, reset the database password in
  Supabase and update `AGROAI_DATABASE_URL` in Render. If a station key leaks, use **New key**.

## Troubleshooting

| Symptom | Likely cause and fix |
|---|---|
| `/health/ready` shows `"database":"unavailable"` | Wrong database URL. Check the password, that you used the *Session pooler* string, and that `?sslmode=require` is at the end. Update the variable in Render → Environment. |
| Render deploy fails on start with "AGROAI_SECRET_KEY must be set" | The generated key is missing. Add `AGROAI_SECRET_KEY` in Render → Environment with a long random value. |
| Website says "Cannot reach the AgroAI server" | The API is waking up (wait a minute and retry), or the API address the website was built with is wrong (see step 3). It must be the bare API URL, without `/api/v1`. |
| Requests blocked by CORS in the browser console | `AGROAI_CORS_ORIGINS` in Render must be `https://kenttolo.github.io` (no path, no trailing slash). |
| No **Admin dashboard** in the menu | The account's email doesn't match `AGROAI_ADMIN_EMAILS`. Fix the variable in Render; the change applies after the automatic redeploy. |
| Weather card shows a request-limit error | Open-Meteo's daily limit was reached for the server's IP. It resets daily; existing history keeps working. |
