# Model card: AgroAI crop recommender

## Summary

| | |
|---|---|
| Task | Multi-class classification: which of 22 crops best suits a set of growing conditions |
| Algorithm | Random Forest (scikit-learn, 300 trees) |
| Inputs | Nitrogen, phosphorus, potassium (kg/ha), temperature (°C), relative humidity (%), soil pH, rainfall (mm) |
| Output | A probability (vote share) for each crop; the API returns the top *k* |
| Held-out accuracy | **99.32%** (macro F1 0.993, log loss 0.053) on a stratified 20% test split |
| Training code | [`backend/app/ml/train.py`](../backend/app/ml/train.py) |
| Reproduce | `make train` (fixed random seed 42) |

Each trained artifact is written with `model_metadata.json`, which records the version, dataset
SHA-256, metrics, candidate comparison and library versions. The API stores that version on every
recommendation so results can be traced to the model that produced them.

## Data

The [Crop Recommendation Dataset](https://www.kaggle.com/datasets/atharvaingle/crop-recommendation-dataset)
(`backend/data/crop_recommendation.csv`): 2,200 rows, 100 per crop, no missing values. The loader
validates columns and value ranges before training.

Crops: apple, banana, black gram, chickpea, coconut, coffee, cotton, grapes, jute, kidney beans,
lentil, maize, mango, moth beans, mung bean, muskmelon, orange, papaya, pigeon peas, pomegranate,
rice, watermelon.

## Training and selection

1. Stratified 80/20 train/test split.
2. Five candidates compared with stratified 5-fold cross-validation on the training split:

   | Candidate | CV accuracy | CV macro F1 | CV log loss |
   |---|---|---|---|
   | **Random Forest** (shipped) | 0.9938 ± 0.0055 | 0.9937 | 0.060 |
   | Gaussian Naive Bayes | 0.9949 ± 0.0042 | 0.9949 | 0.016 |
   | Extra Trees | 0.9926 ± 0.0039 | 0.9926 | 0.108 |
   | Logistic Regression | 0.9682 ± 0.0066 | 0.9678 | 0.237 |
   | k-Nearest Neighbours | 0.9631 ± 0.0119 | 0.9626 | 0.182 |

3. The shipped model is evaluated once on the held-out test split, then refit on all 2,200 rows.

### Why Random Forest and not Naive Bayes

Naive Bayes scores marginally better on cross-validation, but the difference is within one
standard deviation. The deciding factor is behaviour on conditions **unlike** the training data,
which is the normal case for Lesotho (cooler and drier than most of the dataset). For a typical
lowland reading (18 °C, 55% humidity, 90 mm rain), Naive Bayes reports 97% certainty for maize,
while the forest gives maize 34% with coffee and mango close behind. The forest's spread honestly
signals that the model is extrapolating; the app surfaces this as a confidence label. Use
`python -m app.ml.train --select-best` to ship the lowest-log-loss candidate instead.

## Evaluation

Per-class F1 on the test split is 1.00 for 16 crops and 0.97–0.98 for black gram, jute, lentil,
maize, moth beans and rice (each a single misclassification among similar crops).

## Intended use

Decision support for smallholder farmers and extension workers choosing what to plant, used
alongside local knowledge. Not intended for automated decisions, credit or insurance assessments,
or regions and crops outside the training data without revalidation.

## Limitations and risks

- **Not Lesotho-specific.** The dataset's origin and sampling conditions are not documented and
  are likely South Asian. Several crops (coconut, coffee, jute, papaya, mango) are unsuitable for
  most of Lesotho, and staples such as sorghum, wheat and potatoes are absent.
- **Optimistic metrics.** The dataset is clean and balanced with well-separated classes; accuracy on
  real field measurements will be lower.
- **Probabilities are vote shares**, not calibrated likelihoods. The UI therefore shows coarse
  confidence bands rather than exact odds.
- **Out-of-range inputs** are flagged by the API (`warnings`) whenever a value falls outside the
  training data's range.
- **Units.** N, P and K are treated as kg/ha, following common use of this dataset; its source does
  not state units definitively.

## Advisory engine

The crop advisor is rule-based, not learned. For each crop and parameter it uses the 10th–90th
percentile of the dataset's observations as the optimal band
([`crop_profiles.json`](../backend/app/data/crop_profiles.json), regenerated by training and
checked in CI). Deviations are graded *slight / moderate / significant* in units of a quarter of
the band's width (with a per-parameter minimum tolerance) and mapped to practical corrective
actions adapted from the original project's expert advice bank.

## Recommended next steps

- Collect labelled outcomes (crop, conditions, yield) from Lesotho fields and retrain or fine-tune.
- Restrict or down-weight crops that are agronomically implausible for the user's agro-ecological zone.
- Calibrate probabilities (e.g. isotonic regression) once local validation data exists.
